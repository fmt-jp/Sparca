# HANABI 設計書（データモデル・レンダリング方式）

仕様書 `docs/spec.md` §17 手順1「データモデルとレンダリング方式を設計する」の成果物。
確定済みの判断は `CLAUDE.md` §5 を参照。

## 1. 全体構成

```
src/
├── model/      ドキュメントのデータ型・生成関数・幾何計算（UI 非依存、純粋関数）
├── engine/     画像処理エンジン（リサンプリング、色調整、ぼかし、マスク）。UI 非依存、ImageData 相当の型のみ扱う
├── history/    Undo／Redo（スナップショット履歴、連続操作の結合）
├── io/         プロジェクト保存・読み込み（.hnb）、画像書き出し
├── render/     ドキュメント → SVG の描画、ラスター結果のキャッシュ
├── store/      エディタ状態（ドキュメント、選択、ツール、表示倍率）と編集コマンド
└── ui/         React コンポーネント（メニュー、ツールバー、キャンバス、レイヤー、プロパティ）
```

依存方向は `ui → store → (model, history, render, io) → engine`。`engine` と `model` は React・DOM に依存せず、Node 上の Vitest で直接テストする。

## 2. データモデル

### 2.1 ドキュメント

```ts
interface SparcaDocument {
  version: 1;
  width: number;            // キャンバス寸法（px）。表示倍率とは無関係
  height: number;
  background: { kind: 'transparent' } | { kind: 'color'; color: string };
  layers: Layer[];          // 配列の先頭が最背面
  assets: Record<AssetId, AssetMeta>; // 画像のメタ情報（画素データ本体は AssetStore）
}

interface Layer {
  id: string; name: string;
  visible: boolean; locked: boolean;
  children: SceneObject[];  // 先頭が最背面
}

type SceneObject = ShapeObject | PathObject | TextObject | ImageObject | GroupObject;
```

すべてのオブジェクトの共通項目：

```ts
interface BaseObject {
  id: string; name: string;
  visible: boolean; locked: boolean;
  opacity: number;          // 0..1
  box: Box;                 // 親（ドキュメント）座標での外接矩形と回転
  effects: Effect[];        // エフェクト（先頭から順に適用。編集情報として保持し、焼き込まない）
}
interface Box { x: number; y: number; width: number; height: number; rotation: number /* 度、矩形中心まわり */ }
```

- **ShapeObject**：`shape` に `rect`（角丸半径を含む）／`ellipse`／`polygon`（頂点数）／`star`（頂点数・内径比）／`line`／`arrow`（矢じりの大きさ）。塗り・線色・線幅を持つ。形状は `box` の内側に描く。直線・矢印は始点・終点を box 内の正規化座標（0..1）で持つ。
- **PathObject**：ベジェ曲線。アンカーと前後ハンドルを box 内の正規化座標で保持（後からアンカー／ハンドル編集できる構造）。閉じたパスかどうかのフラグを持つ。
- **TextObject**：テキスト内容、フォント、サイズ、太字／斜体、色、文字間隔、行間、揃え。ベクターのまま保持する。
- **ImageObject**：元画像 `assetId` と非破壊の加工パイプライン（§4）。
- **GroupObject**：`children: SceneObject[]`。子は**ドキュメント座標のまま**保持し、グループ自体は独自の変形を持たない。グループの移動・拡縮・回転は子それぞれへ同じ変換を適用する（回転は子の中心をグループ中心まわりに回し、子の回転角に加算）。回転済みの子を非等倍で拡縮した場合は外接矩形ベースの近似になる（Fireworks と同等の挙動）。

**エフェクト（Effect）**：`{ id, kind, enabled, strength, ...種類ごとの設定 }`。`kind` は drop-shadow / inner-shadow / glow / inner-glow / bevel-inner / bevel-outer / emboss / blur / zoom-blur / sharpen / brightness-contrast / hue-saturation / curves / grayscale / sepia / invert / color-overlay。トーンカーブ（curves）は `curves: { rgb, r, g, b }` に各チャンネルの制御点 `{ x, y }`（0..255、x 昇順、2〜16 点）を持ち、各色のカーブ → RGB カーブの順に適用する（描画は単調 3 次補間で 256 段の表を作り `feComponentTransfer type="table"`）。`enabled` は一時的なオン／オフ、`strength`（0..1）は適用前とのブレンド率。同じ種類を複数持てる。旧形式 `{ glow, dropShadow }` は読み込み時に配列へ変換する（有効なものだけ、グロー→ドロップシャドウの順）。

**塗り（Fill）**：図形・パスの `fill` とテキストの `color` は、色文字列（`#rrggbb`）か次のグラデーション。`fill` は塗りなし（`null`）も可。

```ts
interface Gradient {
  kind: 'linear' | 'radial' | 'conic';
  stops: { offset: number /* 0..1 */; color: string; opacity: number /* 0..1 */ }[]; // 2つ以上。保存順は任意
  start: Point; // box 内の正規化座標（回転前の box、0..1 の外も可）
  end: Point;
}
```

- 線形：`start`（位置 0）→ `end`（位置 1）。放射：`start` が中心、`end` は外周上の点（正規化座標で円なので、box に合わせて楕円に伸びる）。円錐：`start` が中心、`end` の方向が位置 0 で、時計回り。
- 正規化座標なので、オブジェクトの移動・拡縮・回転・テキスト枠の自動調整に追従する。
- 線（枠線）の色は単色のみ。

`box` を「回転付き矩形」で統一することで、選択ハンドル・プロパティパネル（X, Y, 幅, 高さ, 回転）・保存形式が全種類のオブジェクトで共通になる。

### 2.2 画像データ（AssetStore）

- 画像の画素データは**不変（immutable）なアセット**として `AssetStore`（ID → Blob と デコード済みビットマップ）に保持し、ドキュメントには ID とメタ情報だけを置く。
- 加工結果でアセットを上書きしない。Undo／Redo 履歴がアセットを参照するだけになり、画像データの複製が起きない。
- どの履歴からも参照されなくなったアセットは、保存時に書き出さない。

### 2.3 エディタ状態（ドキュメント外）

ドキュメントに含めず保存もしない状態：選択中オブジェクト ID、**範囲選択（画素選択）**、現在のツール、表示倍率・スクロール位置、未保存フラグ。
範囲選択（矩形／楕円／投げ縄／多角形）は**ドキュメント座標のベクター形状**として保持し、オブジェクト選択とは別のフィールドで管理する。

## 3. レンダリング方式

- キャンバスはドキュメント全体を **1つの SVG** で描画する。`viewBox` はドキュメント座標、表示倍率は SVG の表示サイズで表現する（表示倍率と実寸を分離）。
- 図形・パス・テキストは SVG 要素。
- エフェクトはオブジェクトごとに 1 つの SVG フィルターにまとめる（`render/effects.tsx`）。リストの先頭から順に、前の結果（最初は `SourceGraphic`）を入力にしてフィルター要素をつなぐ。強さが 1 未満なら `feComposite operator="arithmetic"` で前の結果とブレンドする。シャドウ・グローは結果のアルファ（`feColorMatrix`）からぼかし・膨張・オフセット・塗り（`feGaussianBlur`／`feMorphology`／`feOffset`／`feFlood`）、内側系はアルファの反転を元の形で切り抜く。ベベル・エンボスは Fireworks の「滑らか」な断面に合わせ、ぼかしたアルファを高さマップとして `feDiffuseLighting`（`feDistantLight`、仰角 50°、`kernelUnitLength=1` で表示倍率に依存しない）で照らし、平らな面より明るい分を白、暗い分を黒の半透明として重ねる。外側ベベルの縁はアルファをぼかして閾値処理した「角の丸い膨張」で作り、縁の色で塗ってから陰影を付ける。色の調整は `feComponentTransfer`／`feColorMatrix`（明るさ・コントラストは画像の色調整と同じ式）。SVG フィルターは入力を拡大縮小できないため、ぼかし（ズーム）はフィルターの外で描く：エフェクト列をズームの位置で区切り、前半を1つのフィルターとして適用した結果を、中心を基準に 100% から 100%＋量 まで拡大した複製（流れの長さに応じて 6〜64 枚）として重ねて平均し（8 ビットの丸め誤差を抑えるため半分ずつ不透明度で平均する木構造）、後半のエフェクトはその全体に別のフィルターとしてかける。複製の間隔が 1.5px を超える場合は軽いガウスぼかしで段差をなじませる。フィルターはオブジェクトの回転した座標系で働くため、角度は回転を打ち消して画面上で一定の向きにする。
- 画像は画像エンジンでパイプラインを適用した結果（§4）を `<image>` として配置する。
- グラデーション：線形・放射は SVG の `linearGradient`／`radialGradient`（`gradientUnits="userSpaceOnUse"` と box への変換行列）。SVG に円錐グラデーションはないため、Canvas の `createConicGradient` で画像（長辺 最大 2048px、小さい図形は 2 倍密度）を生成し `pattern` として塗る。生成画像はキャッシュする。
- 選択ハンドル・範囲選択の点線などの操作 UI は、ドキュメント SVG の上に重ねた別レイヤーで描画し、書き出しには含めない。
- キャンバス外のオブジェクトはドキュメントに残し、作業領域には表示する（書き出し対象はキャンバス内のみ）。
- **書き出し**：同じ描画関数で書き出し用 SVG（画像は data URL 埋め込み、操作 UI なし、viewBox ＝キャンバス）を生成し、Canvas に描画してから PNG／JPEG／WebP にエンコードする。画面と書き出しで描画経路が同じになり、見た目が一致する。
- **補間方式**：画像サイズ変更は画像エンジンが指定方式で画素を生成し、box を新しい画素寸法に合わせる（等倍表示）。ブラウザ側のリサイズで補間方式が無視されることはない。選択ツールでの自由変形（ハンドルでの拡縮）はブラウザの描画補間で表示する。正確な補間が必要な場合は「画像サイズ変更」を使う（UI に明記）。

## 4. ラスター加工パイプライン（非破壊）

```ts
interface ImageObject extends BaseObject {
  type: 'image';
  assetId: AssetId;                 // 元画像（変更しない）
  pipeline: {
    crop?: { x; y; width; height }; // 元画像ピクセル座標での切り抜き
    resize?: { width; height; method: ResampleMethod };
    adjust: { brightness; contrast; saturation; temperature; tint; auto?: AutoParams };
    localEdits: LocalEdit[];        // 選択範囲へのぼかし { kind: 'blur', radius } ／モザイク { kind: 'mosaic', size }（マスクは画像内の正規化座標）
  };
}
```

- 適用順は固定：**切り抜き → リサイズ → 色調整 → 部分加工（localEdits：部分ぼかし・部分モザイク。記録順に適用）**。
- 画像全体のぼかしはエフェクト「ぼかし」で行う（2026-10-23 にパイプラインの `blur` を廃止。以前のファイルの `blur` は読み込み時に同じ半径のぼかしエフェクトへ変換する。エフェクトのぼかしは画像の外側へもにじむ）。
- 範囲選択でのぼかしは、選択形状を画像内の正規化座標（0..1）へ変換したマスクとして `localEdits` に記録する。後でリサイズしてもマスクは追従する。
- 選択範囲とマスクはエッジ情報 `MaskEdge { grow?, antialias?, feather? }` を持つ（Fireworks の「エッジ」と「選択範囲を拡張／縮小」）。選択範囲ではドキュメントの px、マスクでは処理後画像の px（記録時に「画像 px／ドキュメント px」で換算。縦横で異なる場合は平均）。ラスタライズの手順：形状をアンチエイリアス付きで塗る → `grow`≠0 なら、内側／外側画素へのユークリッド距離変換（Felzenszwalb–Huttenlocher、線形時間）と境界画素の被覆率から求めた符号付き距離で輪郭を移動（拡張では角が丸くなる）→ `antialias: false` なら 50% で二値化（ハード）→ `feather`>0 なら σ = feather/2 のガウスぼかし（輪郭の ±feather px ほどでなだらかに変化）。範囲外の選択部分が画像の端に偽の輪郭を作らないよう、grow・feather の届く幅だけ余白を付けた格子で計算してから切り出す。
- 選択ツールのエッジ設定（ハード／アンチエイリアス／ぼかし＋幅 0〜100 px）はブラウザごとの設定として保存し、新しい選択範囲と現在の選択範囲に適用する。拡張／縮小は現在の選択範囲の `grow` に加算する（新しい選択範囲は 0 から）。拡張／縮小した選択範囲の点線は、ドキュメント座標で被覆率を計算（長辺最大 512 格子）し、50% の等値線（マーチングスクエア）を描く。ぼかし（feather）は輪郭の内外へ対称に効くため 50% の線は元の輪郭とほぼ同じで、点線は元の形のまま（ドラッグ中の計算を避ける）。
- 自動カラー調整は、実行時に解析したパラメータ（チャンネル別の黒点・白点と、ホワイトバランスのガンマ `gamma`。旧ファイルはゲイン `gains`）を `adjust.auto` に**数値として保存**する。開き直しても同じ結果になる。
- パイプライン結果はパラメータのハッシュでキャッシュする。重い処理は Web Worker で実行し、スライダー操作中は表示サイズに縮小したプロキシで高速プレビューし、確定後に原寸で計算する。
- 加工前後の比較は、パイプラインを無効にした元画像の表示に一時的に切り替えて行う。

### 4.1 リサンプリング（`engine/resample`）

分離可能な畳み込みフィルター（横→縦の2パス）で実装する。縮小時はフィルター幅を縮小率で広げる（アンチエイリアス）。アルファは乗算済み（premultiplied）で計算し、縁の色にじみを防ぐ。

| 方式 | カーネル | 半径 |
|---|---|---|
| 最近傍 | 最も近い画素 | – |
| バイリニア | 三角（tent） | 1 |
| バイキュービック | Keys 3次畳み込み a=−0.5 | 2 |
| Lanczos | Lanczos3（sinc × sinc窓） | 3 |
| バイキュービック・シャープ | Keys a=−0.75 で補間後、アンシャープマスク（半径 0.8px、量 0.5、閾値 0） | 2 |
| バイキュービック・スムーズ | Mitchell–Netravali B=1/3, C=1/3 | 2 |

### 4.2 色調整（`engine/color`）

- 明るさ（−100..100）：加算オフセット。コントラスト（−100..100）：中間灰（128）を中心にしたゲイン。彩度（−100..100）：Rec.709 輝度を基準に色差を拡縮。色温度（−100..100）：R と B のゲインを逆方向に変化。色かぶり補正（−100..100）：G のゲイン。グレースケール・セピアは画像の色調整には持たず、エフェクト（grayscale／sepia）で行う（2026-10-22〜23 に一時的にあった画像の「色調」設定は、読み込み時に同名のエフェクトへ変換する）。
- 自動カラー調整：チャンネル別ヒストグラムの両端 0.5% をクリップして黒点・白点を求め、レベルを伸長。続けて**中間調のニュートラル化**（Photoshop の「自動カラー補正」の「中間調をスナップ」と同じ考え方）でホワイトバランスを補正する。
  - 伸長後の画素のうち、ほぼグレー（彩度 (max−min)/max < 0.15）かつ中間の明るさ（平均 40〜215）の画素だけを集め、その R, G, B の平均を求める。
  - 各チャンネルにガンマ γ = ln(目標)/ln(平均) をかけ（目標は 3 チャンネルの平均、値は 0..1 に正規化）、その平均をグレーに合わせる。γ は 0.67..1.5 に制限。ガンマなので黒点・白点は動かない。
  - 該当画素が全体の 1% 未満なら、色の基準がないとみなしてバランスは変えない（レベル補正のみ）。
  - 以前のグレーワールド法（全画素の平均を揃えるゲイン）は、料理・夕焼け・肌など暖色が多い画像を青く補正してしまうため 2026-10-22 に置き換えた。旧方式で保存されたファイルは `gains` をそのまま適用し、同じ見た目で開ける。

### 4.3 ぼかし（`engine/blur`）

ガウスぼかしを3回のボックスぼかしで近似（分離可能、O(n)）。乗算済みアルファで計算する。部分ぼかしは、ぼかした画像と元画像をマスク（アンチエイリアス付きで塗った形状）でブレンドする。部分モザイクも同様に、モザイク画像（画像の左上から `size`×`size` のブロックに区切り、アルファで重み付けした平均色で塗る）をマスクでブレンドする。ブロックの大きさは処理後画像の px（縮小プレビューでは倍率に合わせて縮める）。

## 5. Undo／Redo

- ドキュメントは不変データとして扱い、編集は Immer で新しいドキュメントを作る（構造共有により、変更のない部分はコピーされない）。
- 履歴は「編集前ドキュメントへの参照」の列。画素データは不変アセットの参照なので、履歴に画像の複製は生じない。
- 連続操作の結合：ドラッグやスライダー操作は `beginTransaction`／`commit` で1つの履歴にまとめる。同じ結合キー（例：`opacity:<id>`）の連続編集も1件に結合する。
- 対象：オブジェクトの作成・変形・プロパティ変更・削除、レイヤー操作、画像加工、キャンバスサイズ変更、トリミング。表示倍率や選択状態の変更は履歴に含めない。

## 6. プロジェクト形式 `.hnb`

ZIP（JSZip）形式：

```
document.json        SparcaDocument（format: "hanabi"。version フィールドでスキーマ移行に対応）
assets/<assetId>.<ext>  元画像のバイト列（読み込んだファイルのまま。PNG/JPEG/WebP 等）
```

- 読み込み時は `document.json` の構造を検証し、参照されている全アセットの存在を確認する。不足や不正な値があればドキュメントを開かずに理由を表示する。
- 画像は常に埋め込むため、元ファイルの移動で参照切れは起きない。

## 7. 画像書き出し

- PNG：透明背景をそのまま出力。
- JPEG：透明部分は背景色（ドキュメント背景色、透明背景の場合は白。ダイアログで変更可）で塗りつぶす。品質 0..100。
- WebP：透明対応、品質 0..100。
- SVG（2026-10-24 追加、ユーザー承認の方針：Web 表示用、テキストは文字のまま、画像は埋め込み、エフェクトは SVG フィルター）：上記の書き出し用 SVG をそのままファイルにする（XML 宣言付き）。非表示のもの、およびストローク幅・エフェクトの届く範囲（`effectsMargin`、ズームぼかしの到達距離）を含めてもキャンバスにかからないオブジェクトは除く。レイヤーは `data-name` にレイヤー名を持つ `<g>`。埋め込む画像は PNG／JPEG／WebP 以外（BMP、アニメーションの可能性がある GIF）を PNG に変換する（ラスター書き出しも同じ経路で、見た目は変わらない）。SVG の読み込み（再編集）とテキストのアウトライン化は対象外。
- 書き出しダイアログで「レイヤー構造や編集情報は保存されない。再編集には .hnb で保存」と表示する。

## 8. 検証と制限

- 最大寸法：一辺 16384px、総画素数 1億（ブラウザの Canvas 上限に配慮）。超える入力は拒否して理由を表示する。
- 画像の読み込み失敗、書き出し失敗、プロジェクトの読み込み失敗は、原因を日本語で通知し、ドキュメントは変更しない。

## 線種・ツールごとの初期設定・ライン（2026-10-24 追加、ユーザー承認）

- 線種：`Paint.strokeStyle?: 'solid' | 'dashed' | 'dotted'`（省略時は実線。以前のファイルと互換）。描画は `stroke-dasharray` を線幅に比例させる（破線 4w/2w・端は butt、点線 0/2w・端は round）。
- ツールごとの初期設定：`ToolDefaults`（ライン／図形／矢印／ペン／テキスト）。ドキュメントではなくブラウザごとの設定（localStorage `sparca.toolDefaults`、読み込み時に検証）。描画ツールが選ばれている間はプロパティパネルの先頭に表示して編集し（選択中のオブジェクトがあれば、その設定は「選択中のオブジェクト」として下に表示）、作成時にオブジェクトへコピーする。
- ライン：ラインツールは 2 アンカーの開いた `PathObject` を作る（部分選択で編集可能）。旧形式の `ShapeGeometry.line` は描画・読み込みとも引き続き対応し、部分選択ツールで扱うときにパスへ変換する（`lineToPath`、同じ id・box・塗り・エフェクト。Undo 1 回）。変換は部分選択ツールへの切り替え時・部分選択でのクリック時・ダブルクリック／右クリックの「パスの編集」時のみ行い、Undo で戻した直後に再変換しない。
- 複製して移動：選択ツールで Ctrl（または Alt／⌘）を押しながらドラッグすると、選択中のオブジェクトを元の真上に複製し、複製の方を動かす（Undo 1 回で取り消し）。キーの状態はドラッグ中ずっと見ていて（ポインタの移動とキーの押し離しの両方）、途中で押すと元を元の位置に戻して複製を作り、途中で離すと複製を消して元を動かす（2026-10-30、Fireworks／Illustrator と同じ動き）。

## パスに変換（2026-10-29 追加）

- `model/shapeToPath.ts`：図形の形状を同じ箱（box）の正規化座標の `PathNode` 列に変換する。箱を変えないので、見た目・グラデーション（箱基準の座標）・回転・エフェクトがそのまま一致する。id・名前・塗り・線・状態も引き継ぎ、型だけ `path` になる（保存形式の追加はない）。
- 楕円：上・右・下・左の 4 点。角丸矩形：角ごとに 2 点（辺の端）と 1/4 円の 3 次ベジェ（ハンドル長 = 半径 × 4/3·(√2−1)）。辺が消える（半径＝辺の半分）所の 2 点は 1 点にまとめる。多角形・星・ブロック矢印は `render/shapes.ts` の頂点計算をそのまま使った角の点。旧形式の矢印（線＋矢じり）は 1 本のパスで同じ見た目にならないため対象外。
- 選択中の図形と、選択中のグループ内の図形をまとめて 1 回の編集（Undo 1 回）で置き換える。

## パスの結合と複合パス（2026-10-29 追加、ユーザー承認：確定方式・複合パス新設・曲線のまま計算・一番下の図形の見た目を継承）

- 複合パス：`PathObject.subpaths?: PathContour[]`（`nodes`／`closed` が 1 本目、`subpaths` が 2 本目以降）。描画は全アウトラインを 1 つの `<path>` にまとめ `fill-rule="evenodd"`（中に入ったアウトラインが穴になる。結合結果は互いに重ならないので向きに依存しない）。`subpaths` がない以前のファイルは単純なパスのまま。箱の当てはめ（`docContoursToPath`）は全アウトラインを囲む。
- 部分選択：編集中のアウトライン番号を `EditorState.nodeContour` に持ち、`editablePath` はそのアウトラインだけを単純なパスとして見せる（既存の点の編集はそのまま動く）。書き戻しは `writePathContour` で該当アウトラインだけを差し替えて箱を当てはめ直す。ほかのアウトラインは点線（`data-contour`）で表示し、クリックで切り替える。
- 計算：`engine/pathBoolean.ts`（paper.js 0.12.18 の paper-core。`eval` を使わないため CSP と両立。約 200 KB を分割ファイルにして起動直後に読み込む）。入力は各オブジェクトの閉じたアウトライン（文書座標。図形は `shapeToPath` 経由）。合体＝全体の和、型抜き＝一番下 −（残り）、交差＝全体の積、中マド＝順に排他的論理和。結果のアウトラインを回転 0 の箱に当てはめる。
- 編集：`store/pathCombine.ts` が選択の検査・重なり順（文書内の順）・見た目の継承・1 回の編集での置き換えを行う（計算関数を引数で受け取るので単体テストできる）。最新の paper.js（0.13 以降）は公開から日が浅いため、実績のある 0.12.18 に固定した。

## 選択範囲の消去とテキストのパスへの添付（2026-10-29 追加、ユーザー承認）

- 消去：`LocalEdit` に `{ kind: 'erase', mask }` を追加（部分ぼかし・モザイクと同じ非破壊の部分加工。マスクのエッジ・拡張／縮小も同じ）。パイプラインでは `eraseWithMask`：アルファだけを (1 − 被覆率) 倍し、色は残す（縁が黒ずまない）。範囲選択があって対象画像があるとき Delete は消去、Ctrl+X はコピー後に消去（「選択範囲をカット」1 回の Undo）。範囲選択がなければ Delete は従来どおりオブジェクト削除。
- パス上のテキスト：`TextObject.path?: TextOnPath`（パスのアンカーをテキストの箱で正規化して保持し、箱はパスの箱と同じ。開始位置 0〜1・方向・逆方向・パスからの距離 px、外したときに戻す元のパスの見た目 `source`）。Fireworks と同じく 2 つを 1 つのテキストにまとめ、パスは描かない。`fitTextBox` はパス上のテキストの箱を変えない。
- 描画は `render/textOnPath.ts`：パスを折れ線にして長さで引き、文字ごとに幅を測って（Canvas の measureText、カーニングなし）中心の位置と接線の角度を求め、`<text>` を 1 文字ずつ transform で置く（回転＝rotate(θ)、垂直＝なし、傾斜（縦方向）＝skewY(θ)、傾斜（横方向）＝skewX(−θ)、傾斜は ±60° まで）。SVG の textPath は回転以外に対応しないため使わない。文字はパスの外にはみ出すので、エフェクトのフィルター範囲を文字の大きさ分広げる。
- 添付：テキスト 1 つ＋パスまたは図形（`shapeToPath`）1 つ。テキストの重なり順の位置に置き、パスのオブジェクトは削除。開始位置はテキストの揃えに合わせて 0／0.5／1。外す：元のパスを同じ箱・見た目で作り直してテキストのすぐ下に置き、テキストはパスの箱の上辺から揃えに応じて吊るす。
