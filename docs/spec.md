# Sparca 開発仕様書
**Version:** 0.1  
**Project name:** Sparca  
**Product type:** ハイブリッド型グラフィックエディタ（ベクター＋ラスター）

## 1. プロジェクト概要

### 1.1 目的

Macromedia Fireworksにインスパイアされた、軽快で直感的な画像・グラフィック編集アプリケーション「Sparca」を開発する。

Fireworksの操作性や、写真・図形・文字を一つのキャンバス上で扱える利便性を参考にしつつ、現代の技術で再構築する。

Photoshopのような高度な写真加工機能をすべて再現することを目的とせず、日常的な画像加工、注釈の追加、図形描画、Web素材作成などを簡単に行えることを重視する。

### 1.2 基本コンセプト

- 写真・ラスター画像を加工できる。
- ベクター図形やテキストを作成・編集できる。
- ベクターとラスターを同一キャンバス上で組み合わせられる。
- オブジェクトを後から個別に編集できる。
- レイヤーによってオブジェクトを管理できる。
- 操作方法を分かりやすくし、設定を探す手間を減らす。
- Undo／Redoによって安心して編集できる。
- まず実用的な初期版を完成させ、実際の使用結果に基づいて改善する。

## 2. 開発方針

### 2.1 基本方針

開発者は、一般的なグラフィックエディタの操作方法を参考に、合理的な標準動作を判断して実装する。

ユーザーによる指定がない細部について、事前確認を繰り返さない。まず動作するアプリケーションを作成し、実際に使用した結果をもとに改善する。

ただし、データ形式、画像処理方式、レンダリング方式など、後から変更すると大きな手戻りが発生する設計は、初期段階で適切に設計する。

### 2.2 開発上の優先事項

1. 基本機能が実際に動作すること。
2. ベクターとラスターを統合して編集できること。
3. 編集内容を保持し、後から再編集できること。
4. 操作性と視認性がよいこと。
5. Undo／Redoや保存・復元が正しく機能すること。
6. 機能を後から追加・拡張しやすいこと。

画面だけを作ったモックアップではなく、実際に操作できるアプリケーションを完成させる。

## 3. 技術構成

### 3.1 推奨技術

Web技術を利用したデスクトップ向けグラフィックエディタとして実装する。

- React
- TypeScript
- Vite
- SVG：ベクター図形、パス、テキスト、選択ハンドルなど
- Canvas／ImageBitmap等：ラスター画像の描画・画像処理
- CSS：UIレイアウトとスタイリング

必要に応じて、画像処理ライブラリや色調整・フィルター処理用のモジュールを採用する。

上記は初期の推奨構成であり、実装時にライブラリの互換性、保守性、性能を確認して選定する。

### 3.2 設計原則

- UIと画像処理エンジンを分離する。
- 編集ドキュメント、レイヤー、オブジェクトのデータモデルを明確に定義する。
- 画像処理方式をUIから独立して切り替えられるようにする。
- Undo／Redoを一貫した編集履歴として管理する。
- 画面表示用のプレビューと最終書き出しを区別する。
- ブラウザ標準のリサイズ処理に依存して、指定した補間方式が無視される構成にしない。
- 長時間の画像処理でUIが停止しないよう、必要に応じてWeb Worker等を利用する。

## 4. 画面構成

### 4.1 全体レイアウト

画面は以下の構成とする。

- 上部：メニューバー、共通操作、表示倍率、保存・書き出しなど
- 左側：ツールバー
- 中央：キャンバスと作業領域
- 右側：レイヤーパネル
- 下部：選択中のツールまたはオブジェクトの詳細設定パネル

基本レイアウトは、左・中央・右・下の4領域を維持する。

パネル幅や高さは、作業領域を圧迫しない範囲で調整可能にすることを推奨する。

### 4.2 左ツールバー

**アイコン主体＋ツールチップ＋関連ツールのグループ化**を採用する。

- 通常時はアイコンを表示する。
- マウスホバー時にツール名を表示する。
- 必要に応じてキーボードショートカットも表示する。
- 選択中のツールを視覚的に強調する。
- 関連するツールはグループ化する。
- グループ内のツールは、クリックまたは長押しなどの分かりやすい操作で切り替えられるようにする。
- アイコンの大きさ、線の太さ、余白を統一する。

ツール名が常時表示される形式ではなく、作業領域を広く確保できる形式とする。

## 5. ツールバーの機能

### 5.1 基本ツール

- 選択ツール
- トリミングツール

選択ツールは、キャンバス上のオブジェクトを選択し、移動、拡大縮小、回転などを行う。

トリミングツールは、キャンバスまたは画像の切り抜きを行う。画像単体のトリミングと、ドキュメント全体のキャンバス範囲変更を混同しないようにする。

### 5.2 ビットマップ／ラスター関連ツール

範囲選択ツールとして以下を用意する。

- 矩形選択
- 楕円選択
- 投げ縄選択
- 多角形選択

追加の補助ツールとして、以下を用意する。

- スポイト
- 手のひら（キャンバス移動）
- ズーム

将来的な拡張候補：

- ブラシによる選択
- フリーハンド描画
- 部分ぼかしブラシ

範囲選択は選択範囲を保持し、対象画像の画素に対して加工できるようにする。

少なくとも設計上、範囲選択とオブジェクト選択は明確に区別する。

### 5.3 ベクターツール

以下を用意する。

- ラインツール
- ペンツール（ベジェ曲線）
- 矩形
- 角丸矩形
- 楕円・円
- 多角形
- 星
- 矢印
- テキスト

図形はベクターオブジェクトとして保持し、作成後も個別に編集できるようにする。

ベジェ曲線は、将来的にアンカーポイントやハンドルを編集できる設計とする。

### 5.4 画像配置

画像ファイルをキャンバスに配置できるようにする。

画像はラスターオブジェクトとしてレイヤーに追加し、移動、拡大縮小、回転、透明度変更などを行えるようにする。

## 6. キャンバスとオブジェクト編集

### 6.1 キャンバス

- 任意の幅・高さを設定できる。
- 背景色または透明背景を扱える。
- 表示倍率を変更できる。
- 拡大表示中にキャンバスを移動できる。
- オブジェクトの位置・寸法・回転を表示する。
- 選択中のオブジェクトに変形ハンドルを表示する。

キャンバスの表示倍率と、実際のドキュメント寸法は分離して管理する。

### 6.2 オブジェクト編集

オブジェクトに対して以下の操作を可能にする。

- 選択・選択解除
- 移動
- 拡大縮小
- 回転
- 複製
- 削除
- コピー・ペースト
- 前面・背面への移動
- 整列
- 必要に応じたグループ化・グループ解除

Shiftキーなどによる縦横比固定、正円・正方形の描画など、一般的なグラフィックエディタの操作を採用する。

具体的なキー割り当ては、実装時に一貫性を保って定義する。

## 7. ラスター画像の基本編集

### 7.1 画像サイズ変更

画像のピクセル寸法を変更する機能を用意する。

以下の2方式を切り替えられるようにする。

**ピクセル指定**

- 幅（px）
- 高さ（px）

**比率指定**

- 元画像に対する拡大・縮小率（%）

共通仕様：

- 縦横比固定の有効・無効を切り替えられる。
- 縦横比固定時は、一方の値を変更すると他方を自動計算する。
- 縦横比固定を解除した場合は、幅と高さを個別に指定できる。
- 入力値の妥当性を検証する。
- 処理後の寸法を確認できる。
- 元画像を保持し、変更をやり直せるようにする。

### 7.2 リサイズ補間方式

**バイキュービック法を必須実装とする。**

補間方式は選択式にし、以下を用意する。

1. 最近傍法（Nearest Neighbor）
2. バイリニア法（Bilinear）
3. バイキュービック法（Bicubic）
4. Lanczos法
5. バイキュービック・シャープ
6. バイキュービック・スムーズ

初期設定はバイキュービック法とする。

各方式の用途：

- 最近傍法：ドット絵、ピクセルアート
- バイリニア法：軽量な一般用途
- バイキュービック法：写真の一般的な拡大・縮小
- Lanczos法：写真の高品質な縮小など
- シャープ系：縮小時の輪郭強調
- スムーズ系：拡大時の滑らかさ重視

シャープ／スムーズ方式は、基本のバイキュービック法に対する調整方式として定義する。実装するアルゴリズムとパラメータは明確にし、単なる名称違いにならないようにする。

拡大・縮小のどちらでも補間方式を選択できるようにする。

可能であれば変更前後のプレビューを提供する。

### 7.3 キャンバスサイズ変更

画像の画素寸法を変更する機能とは別に、キャンバスの寸法を変更する機能を用意する。

指定項目：

- 幅（px）
- 高さ（px）
- 基準位置

基準位置は9点から選択できるようにする。

- 左上
- 上中央
- 右上
- 左中央
- 中央
- 右中央
- 左下
- 下中央
- 右下

基準位置は、サイズ変更時に既存コンテンツをどこに維持するかを決める。

例：

- キャンバス幅を1200pxから1400pxへ変更し、中央基準にする場合、左右に100pxずつ余白を追加する。
- キャンバス高さを800pxから1000pxへ変更し、左上基準にする場合、右側と下側に余白を追加する。
- キャンバス幅を1200pxから1000pxへ変更し、右中央基準にする場合、左側を200px分切り落とす。

キャンバスを小さくした際に範囲外になるオブジェクトは、原則としてドキュメント内に保持し、キャンバス内のみを通常の表示・書き出し対象とする。

キャンバスサイズ変更によって、内部の画像や図形を自動的に拡大縮小しない。

### 7.4 トリミング

トリミングツールで対象範囲を指定できるようにする。

- ドラッグによる範囲指定
- 範囲の調整
- 確定・キャンセル
- Undoによる復元

ドキュメント全体のトリミングと、個別ラスター画像のトリミングは、内部処理で混同しないこと。

### 7.5 カラー調整

以下を実装する。

- 自動カラー調整
- 明るさ
- コントラスト
- 彩度
- 色温度などの色味調整

手動調整は、スライダーまたは数値入力で操作できるようにする。

自動調整は、画像に応じた補正を実行する機能とする。実装する補正アルゴリズムを明示し、単に固定値を適用するだけの処理にしない。

調整結果はプレビューで確認でき、Undo／Redoで復元できるようにする。

### 7.6 ぼかし

ガウスぼかしなどの基本的なぼかし機能を実装する。

- ぼかし強度を指定できる。
- 画像全体への適用に対応する。
- 選択範囲への適用に対応する。
- 元画像を可能な限り保持する。
- 加工前後を確認できるようにする。

ブラシを使った部分的なぼかしは、初期版では必須とせず、後から追加可能な設計にする。

## 8. ベクター図形の編集

### 8.1 基本図形

以下の図形を作成できるようにする。

- 矩形
- 角丸矩形

- 多角形

- 位置（X、Y）
- 幅・高さ
- 回転角度
- グラデーション（将来的な拡張を考慮）
- グロー
- ドロップシャドウ

図形は、作成後も各プロパティを変更できるようにする。

### 8.3 スポイト

キャンバス上の色を取得し、図形や文字の色に設定できるようにする。

画像から取得した色を塗りや線の色に利用できること。

## 10. レイヤー管理

### 10.1 基本構造

レイヤーパネルで、ベクターオブジェクトとラスター画像を統合管理する。

オブジェクトをレイヤーとして管理する方式、またはレイヤー内に複数オブジェクトを配置する方式のどちらを採用する場合も、将来のグループ化や拡張に対応できる階層構造を持たせる。

推奨する概念構造：

Document  
├── Layer  
│   ├── ImageObject  
│   ├── ShapeObject  
│   └── TextObject  
└── Layer  
    ├── PathObject  
    └── ShapeObject

### 10.2 レイヤー操作

- 新規作成
- 削除
- 複製
- 名前変更
- 表示／非表示
- ロック／解除
- 順序変更
- ドラッグ＆ドロップによる並べ替え
- グループ化
- グループ解除

グループ化したオブジェクトは、まとめて移動・変形できるようにする。

レイヤーの順序はキャンバスの描画順序に反映する。

レイヤーの表示／非表示やロック状態は、編集操作と一貫して動作させる。

## 13. 保存・プロジェクト形式

### 13.1 編集プロジェクト

編集可能な状態を保持するため、Sparca独自のプロジェクト形式を設ける。

プロジェクト形式は、少なくとも以下を保存する。

- キャンバス寸法
- 背景設定
- レイヤー構造
- オブジェクトの種類
- オブジェクトの位置・寸法・回転
- 図形のパス・形状
- テキスト内容と装飾
- 画像データまたは画像への参照
- 画像調整パラメータ
- 表示・ロック状態
- グループ構造

保存後にプロジェクトを開き直した場合、編集可能な状態を復元できること。

画像への参照切れや保存先の変更に対応できる設計とする。必要に応じて、画像をプロジェクト内に埋め込む形式を採用する。

プロジェクトの保存・読み込みが確実に動作することを優先し、独自拡張子は実装時に決定する。

### 13.2 画像書き出し

初期版では以下の形式を対象とする。

- PNG
- JPEG
- WebP

書き出し対象は、キャンバスの範囲内に合成された画像とする。

- PNG：透明背景に対応
- JPEG：品質設定を用意し、透明部分の扱いを明確にする
- WebP：品質設定を用意する

書き出し時に編集用レイヤー構造が失われることを、UI上で分かるようにする。

SVG書き出しは拡張候補とする。ベクター情報を保持できる範囲と、ラスター画像の扱いを明確にする。

## 14. 操作性・安全性

- 編集中のドキュメントに未保存変更があることを表示する。
- 保存前に閉じる場合は、必要に応じて確認する。
- 画像加工前の状態に戻せるようにする。
- 無効な数値入力や極端に大きい画像寸法を検証する。
- 長時間の処理中は進行状況を表示する。
- エラー時にドキュメントが不整合な状態にならないようにする。
- ファイルの読み込みや書き出しが失敗した場合、原因をユーザーが理解できる形で表示する。

## 16. 受け入れ基準

以下を満たした時点で、初期版としての基本機能が成立したと判断する。

1. 画像ファイルを読み込み、キャンバスに配置できる。
2. ベクター図形とテキストを作成できる。
3. ベクターとラスターを同じドキュメント内で重ねて編集できる。
4. レイヤーの順序、表示、ロックを操作できる。
5. 画像のサイズをピクセル指定と比率指定で変更できる。
6. バイキュービック法を含む補間方式を選択できる。
7. キャンバス寸法を変更し、9点の基準位置を選択できる。
8. 明るさ、コントラスト、彩度などの調整が実際に反映される。
9. ぼかしを画像全体または選択範囲に適用できる。
10. テキストや図形にグロー・ドロップシャドウを適用できる。
11. Undo／Redoで主要な編集操作を取り消し・再実行できる。
12. プロジェクトを保存し、再度開いて編集を継続できる。
13. PNG、JPEG、WebPに書き出せる。
14. 画像加工や書き出しが失敗した場合、適切にエラーを通知できる。

各項目は、UIが存在するだけではなく、実際の動作を確認するテストを用意する。

## 17. Claude Codeへの実装指示

この仕様書を開発の基本要件として使用する。

実装に着手する前に、リポジトリの状態を確認し、既存コードがある場合は構成を把握する。空のプロジェクトの場合は、推奨技術を用いて初期構成を作成する。

その後、次の順に進める。

1. データモデルとレンダリング方式を設計する。
2. 最小構成で起動できるアプリを作る。
3. ベクターとラスターの統合キャンバスを実装する。
4. レイヤー、オブジェクト選択、変形を実装する。
5. 画像処理とリサイズ方式を実装する。
6. Undo／Redoとプロジェクト保存を実装する。
7. UIを整え、画像書き出しを実装する。
8. 各機能のテストを実施する。

一度に巨大な実装を生成して終わりにせず、段階ごとに動作確認と修正を行う。

未実装の機能を、実装済みであるかのように表示しない。仕様上の制約や実装できなかった項目があれば、明確に報告する。

READMEには、環境構築、起動方法、テスト方法、主要な設計判断を記載する。

最終的な目標は、見た目だけのデモではなく、ユーザーが実際に画像を読み込み、編集し、保存・書き出しできるSparcaの初期版を完成させることである。
